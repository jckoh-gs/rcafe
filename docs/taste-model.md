# 입맛 모델 (M2)

날씨 → "지금 어울리는 입맛" 과 카페 → "이 카페가 내세우는 입맛" 을 같은 10개 축으로 표현하고, 두 벡터의 유사도로 추천한다.
코드: `backend/app/domain/taste.py`, `backend/app/domain/weather.py`, 사용 예: `backend/README.md`.

## 입맛 축 (0~1)
`hot` 따뜻함 · `iced` 시원함 · `sweet` 달콤함 · `sour_fresh` 상큼함 · `bitter_roast` 깊은 로스팅 ·
`rich_creamy` 진하고 크리미한 · `nutty_cozy` 고소하고 포근한 · `aroma` 향긋함 · `light` 가볍고 산뜻한 · `caffeine_boost` 각성

## 날씨 쪽
1. 관측값(기온·습도·풍속·강수·운량·시각)에서 **체감온도**를 계산한다. 추울 때는 풍속을 반영한 체감온도, 따뜻할 때는 KMA 여름 체감온도(습구온도 기반) 식을 쓴다.
2. 6차원 **날씨 특징 벡터**(체감온도, 습도, 비, 하늘 맑음, 시각 sin/cos)를 만들고 중요도 가중치를 곱한다.
3. 규칙 엔진(`taste_from_conditions`)이 각 날씨에서 원하는 입맛을 정한다. 모든 계수는 조정 가능한 가중치이다.
   근거 문헌의 방향성(더우면 시원·상큼·가벼움, 추우면 따뜻·달콤·진함, 비 오면 고소·포근·향)을 반영하며,
   **효과 크기가 작고 연구 간 결과가 엇갈리므로 사실이 아니라 휴리스틱**이다 (`docs/evidence.md`).
4. 규칙으로 만든 시나리오 306개(체감온도 −12~36℃ × 비/습도 3종 × 구름 2종 × 아침·낮·저녁)를 `taste_archetype`(pgvector, HNSW)에 저장한다.
5. 실제 날씨의 특징 벡터로 **가장 가까운 시나리오 5개를 유사도(L2) 검색**하고, 거리 역가중 평균(70%)과 규칙 엔진 직접 계산값(30%)을 섞어 최종 입맛을 만든다.

## 카페 쪽
- 근거: ① 리뷰에서 많이 언급된 메뉴(`menu_mentions`) ② 메뉴명·설명(앞의 3개는 대표 메뉴로 가중) ③ 방문자 리뷰 10건(평점 가중, 주문 메뉴, 네이버 투표 키워드 "커피가 맛있어요" 등).
- 한국어 **키워드 사전**으로 축 점수를 매긴다. 부정("달지 않아요")과 비슷한 단어("아이스크림", "핫한", "디카페인", "취향")는 제외한다.
  메뉴명 규칙: "자몽에이드" → 상큼+시원, "카페라떼" → 크리미, 온도 표시가 없으면 따뜻/시원 중립(0.5).
  프로모션·옵션 줄("[패스오더전용] 100원 아메리카노", "샷 추가", "딸기케익(2호)")은 메뉴에서 제외한다.
- 카페별 가중 평균 → 데이터셋 전체의 평균·95백분위로 축마다 0~1로 늘리고 → 근거가 적은 카페는 평균 쪽으로 끌어당긴다(`confidence`).
- 추천 유사도는 **평균을 뺀 벡터의 코사인**(모든 카페가 가진 공통 성향이 아니라 두드러진 성향만 비교)이다. 메뉴는 맛 축으로 고르되 날씨와 반대되는 명시적 온도(예: 추운 날 "아이스")는 감점한다.

## 추천 순위의 다듬기 (디저트가 올라오는 문제)
`uv run python -m scripts.eval_reco`가 6가지 날씨 × 13곳 위치(78개 시상대)에서 실제 데이터로 TOP3를 만들어 잰다.

| 지표 | 전 | 후 |
|---|---|---|
| 추천 메뉴가 음료인 비율 | 83% | **100%** |
| 3곳 모두 음료인 시상대 | 58% | **100%** |
| 같은 음료 종류(예: 아메리카노)만 3곳인 시상대 | 10개 | **0개** |
| 종류가 서로 다른 3곳인 시상대 | 31개 | **67개** |
| 약한 근거 문장("리뷰 10건 중 2건에서 향…") | 159문장 중 다수 | 48문장, 모두 3건·30% 이상 |

- 음료가 있으면 음료만 후보로 한다. 음료 판별은 이름 목록으로 하고, "더티 초코 롤"의 "티"처럼 글자만 닮은 경우를 걸러낸다(평가 중에 찾은 버그).
- 빵집(리뷰 언급이 빵 중심)은 점수를 낮추고, 같은 음료 종류가 겹치면 감점한다.
- 추천 이유는 실제 근거만 쓴다: 리뷰에서 그 메뉴 이름이 20번 이상 언급(예: "라떼가 392번 언급") → 리뷰 5건 이상 중 3건·30% 이상이 이 메뉴와 맞는 맛을 언급 → 메뉴 자체의 맛 → 오늘 온도 안내.

## 정확도 측정 (키워드 사전, 그리고 시험해 본 로컬 LLM)
**두 가지 평가를 구분해서 읽는다.**
1. **실제 리뷰 평가(과거, 저장소에 없음)**: 리뷰 200자 요약 120건에 한 명(저)이 손으로 라벨을 붙여 축 단위로 채점했다. 아래 표와 개선 내용은 이 평가의 기록이다.
   원본은 제3자(네이버 이용자)의 글이라 저작권·개인정보 문제로 저장소에서 뺐으므로, 이 수치는 저장소만으로는 다시 만들 수 없다.
2. **가상 문장 회귀 테스트(현재, 저장소에 있음)**: 같은 형식으로 새로 쓴 가상 리뷰 120건(`backend/tests/fixtures/taste_eval.json`, 가상의 가게, 실제 리뷰·작성자 없음).
   `uv run python -m scripts.eval_taste`로 채점하고 `tests/test_taste_eval.py`가 하한을 지킨다. 라벨은 사전의 출력이 아니라 문장의 뜻으로 붙였고, 사전은 이 문장들에 맞춰 고치지 않았다.
   첫 측정은 set1 F1 0.95 · set2 0.90 · set3 0.87이다. 사전을 설계한 사람이 쓴 문장이라 실제 리뷰보다 쉬울 수 있으니(원본 평가보다 높게 나왔다), **사전이 나빠졌는지 보는 용도이지 실제 정확도가 아니다.**
   사전이 틀리는 사례(예: "졸음이 달아났어요"의 "달아", "단맛이 세지 않아서"의 부정, "시나몬 롤" 같은 음식 이름, 쌉싸름·달큰·뜨겁게 같은 놓친 표현)가 이 세트에 그대로 들어 있다. 사전을 고쳐서 이 사례들을 맞추지 않은 것도 같은 이유다.

맛 언급이 없는 리뷰가 절반가량이라, 근거 없이 태그를 붙이면 정밀도가 떨어진다.

| 세트 | 사전 처음 → 지금 (F1) | 비고 |
|---|---|---|
| set1 (40) | 0.71 → 0.92 | 오류를 보고 고친 세트(수치가 부풀려짐) |
| set2 (40) | 0.77 → 0.92 | 같음 |
| **set3 (40, 블라인드)** | **0.74 → 0.82** | 라벨을 먼저 고정하고 규칙 선택에는 쓰지 않음. 정밀도 0.65 → 0.76, 재현율 0.86 → 0.89 |

- 개선 내용: 모양이 비슷한 단어("주차가"의 "차가", "추천드립니다"의 "드립", "앙버터"), 가게를 묘사하는 말("따뜻한 우드 톤", "깔끔한 매장", "시원한 매장"),
  재료 이름(피칸·아몬드·치즈·초코·원두), "라떼위크" 같은 행사명을 걸러냈다. 빙수·캬라멜 등은 추가했다.
- 같은 40건(set1)으로 `qwen3:1.7b`를 돌린 결과 **F1 0.33(예시 프롬프트) / 0.24(예시 없음)**, 리뷰당 약 13초였다. 맛 언급이 없는 리뷰에도 태그를 지어내는 경향이 컸다.
  그래서 사전만 쓰고, 설치했던 Ollama는 모두 삭제했다.
- 한계: 라벨러가 한 명이고 사전도 같은 사람이 설계했으며, 표본이 작다(세트당 40건). 방향은 믿을 수 있어도 소수점 이하 수치는 참고만 한다.
  첫 평가 세트 일부는 화면에 한글이 잘려 보인 채 라벨링해서 전문을 보고 다시 붙였다(그래서 set2는 튜닝용으로만 쓴다).

## 현재 한계
- 로컬 LLM(Ollama)은 시험 후 전부 삭제했다. 이 노드(GPU 없음, 4코어)에서는 느리고 사전보다 부정확했다.
- 리뷰 원문은 입맛 계산 직후 `purge-review-text`로 지운다(태그와 200자 요약만 남김). 사전을 바꾸면 원문이 필요해 상세를 다시 수집해야 한다
  (`UPDATE cafe SET content_hash = NULL` 후 `details --max-age-days 0`).
- 입맛 벡터는 카페당 리뷰 10건과 메뉴 정보에서 만든다. 리뷰가 적은 카페는 평균 쪽으로 끌어당겨(confidence) 과신하지 않는다.

## 명령
```bash
uv run python -m app.adapters.inbound.cli seed-archetypes      # 날씨 시나리오 적재 (멱등)
uv run python -m app.adapters.inbound.cli taste                # 카페 입맛 벡터 계산 (멱등)
uv run python -m app.adapters.inbound.cli preview --temp 33 --humidity 75 --cloud 2 --hour 14
uv run python -m app.adapters.inbound.cli purge-review-text    # 리뷰 원문 삭제 (태그·요약은 유지)
```
